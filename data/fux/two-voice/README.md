# Fux, *Gradus ad Parnassum* — Part I (two voices): game dataset

`fux-two-voice.json` is the game-ready dataset of the 46 two-voice exercises from J. J. Fux,
*Gradus ad Parnassum* (Vienna: van Ghelen, 1725), with Fux's own solutions, the source interval
annotations, and a catalogue of the cantus firmi. The game loads this JSON directly through
`src/music/fux/` and never parses MusicXML at runtime.

- Generated by `tools/fux_import/build_dataset.py`
- Validated by `tools/fux_import/validate.py`; the results are in `VALIDATION.md` and `validation-report.json`
- Rebuild with `npm run data:fetch && npm run data`

## Source and the choice of version

The source is the Four Score and More / Open Music Theory "Gradus ad Parnassum Exercises" dataset by
Mark Gotham. Its upstream repository is <https://github.com/MarkGotham/species>, vendored in
`data/sources/fux-species/` at commit `5c7cae40422bd5ed897a2be3b916a7bc1a2a2df7` (2026-10-07; the
latest tag is `v1.0.0`). The reference pages are
<https://pressbooks.nebraska.edu/openmusictheory/chapter/gradus-ad-parnassum-exercises/> and
<https://fourscoreandmore.org/species/>. Both download from that repository. Neither host was
reachable from the build environment, so the files were taken from the repository itself. These are
the files that the pages call the Part I "Exercises / Solutions / Annotations / Distinct" downloads
(`I/I-*.mxl`).

The upstream repository encodes each exercise four times:

| reading | file(s) | role here |
|---|---|---|
| `kern_vor` | `I/sp*/gap_*.krn` (+ `gap_*.json` metadata) | Declared by upstream as the **version of record**. Supplies the normalized notes. |
| `musicxml_exercise_file` | `I/sp*/gap_*.mxl` | Derived from the krn by upstream scripts. Parsed in full, compared note by note, and its raw `<duration>/<divisions>/<type>/<accidental>` is kept on every note. |
| `musicxml_published` | `I/I-Solutions.mxl` (+ `I-Exercises.mxl`) | The public download. Parsed in full and compared note by note. |
| `musicxml_annotations` | `I/I-Annotations.mxl` | The public download. Supplies the interval annotations. |

At the pinned commit, upstream corrected the krn files of Figs. 22, 85b, 86a and 87b against the
1725 print (commit `67d0247`). Those corrections were not yet propagated to any `.mxl`. The
normalized notes therefore follow the krn. Every MusicXML disagreement is kept in
`solutions[].source.divergences` and `solutions[].source.alternative_readings`, and is listed in
`VALIDATION.md`. To switch the canonical reading, change `CANONICAL_READING` in `build_dataset.py`.

## Notes

```jsonc
{
  "i": 1, "pitch": "F4", "midi": 65, "rest": false,
  "duration": "1/2", "offset": "1/2", "measure": 1, "beat": "1/2",   // fractions of a whole note
  "step": "F", "alter": 0, "octave": 4,
  "tie": "start",                     // start | continue | stop | null
  "accidental_shown": false, "fermata": false, "grace": false,
  "kern": "[2f",                      // original token of the canonical reading
  "musicxml": { "file": "I/sp5/gap_085a.mxl", "measure": "1", "divisions": 10080, "duration": 20160,
                "type": "half", "dots": 0, "accidental": null, "tie": ["start"], "tied": ["start"] },
  "editorial": { ... }                // only where upstream emended the 1725 print (Fig. 33)
}
```

Rests appear as notes with `"rest": true` and a `null` pitch. Pitches are spelled exactly as the
source spells them. There is no transposition and no tonal respelling, and nothing is reduced to
pitch classes.

## Exercises (`exercises[]`)

Each exercise carries the following fields: `id` (for example `fux_2v_fig_085a`), `ordinal` (source
order), `figure`, `species` (one of `first` to `fifth`), `species_number`, `modal_final` (`D E F G A C`),
`cantus_voice` and `counterpoint_voice` (`upper` / `lower`), `meter`, `measures`, and `difficulty`.

`difficulty` is derived from the species number. It is not source data, and its `basis` field says so.

- `cantus_firmus`: `{cf_id, staff, staff_index, clef: {original, modern}, notes[]}`.
- `counterpoint`: `{role: "player", staff, staff_index, clef, notes: [], blank_source[], blank_source_mirrors_solution_rhythm}`.
  - `notes` is always empty.
  - `blank_source` records how `I-Exercises.mxl` writes the empty staff. **In all 46 cases it writes
    rests in the exact rhythm of Fux's solution.** Do not display those rests if the rhythm should
    stay hidden.
- `source`: upstream id, figure data (number, suffix, "corrected version" notes), the raw species
  list, the raw modal final, the CF part (`{part, raw: "Upper"|"Lower"}`), the original 1725 clefs,
  the 1725 page, per-system PDF data (including upstream review notes), the kern reference records,
  and the file paths and measure spans inside each combined file.

## Original solutions (`solutions[]`)

Each solution carries the following fields:

- identifiers and metadata: `id`, `exercise_id`, `role: "original_solution"`,
  `author: "Johann Joseph Fux"`, `cf_id`, `species`, `modal_final`, `cantus_voice`,
  `counterpoint_voice`, and `clefs`
- `cantus_firmus.{pitch_sequence, notes}`
- `counterpoint.{pitch_sequence, duration_sequence, notes}`
- `source.{canonical_reading, files, urls, divergences, alternative_readings, editorial}`

The solution is Fux's own. Nothing is generated or "corrected" according to rules.

## Annotations (`annotations[]`)

Each record is `{id, exercise_id, cf_id, source, items[], unannotated_counterpoint_onsets[]}`, where each item is:

```json
{ "offset": "1/2", "measure": 1, "beat": "1/2", "annotated_voice": "counterpoint",
  "counterpoint_note": "F4", "cantus_note": "F3",
  "interval": "P8",            // the source text (MusicXML lyric in I-Annotations.mxl)
  "interval_computed": "P8",   // recomputed for verification only
  "counterpoint_position": "above", "agrees": true,
  "counterpoint_note_index": 1, "cantus_note_index": 0 }
```

- `counterpoint_note` and `cantus_note` are the pitches *as they stand in the annotated file*.
- When those pitches differ from the canonical reading (Figs. 22 and 87b), the item also carries
  `canonical_counterpoint_note`, `canonical_cantus_note` and `canonical_interval_computed`. The
  source interval text is never overwritten.

## Cantus firmi (`cantus_firmi[]`)

Each CF record carries the following fields:

- identity: `cf_id`, `family_id`, `modal_final`
- the melody: `pitch_sequence`, `midi_sequence`, `duration_sequence`, `length_in_notes`
- register: `range` (lowest, highest, semitones) and `original_register` (first, final, original clefs)
- `notes`
- usage: `source_exercises`, `source_figures`, `cantus_voices`, `distinct_file_entries`, `in_exercises`

A CF's identity is its exact sequence of spelled pitches and durations, register included. That
gives 8 CFs used by the 46 exercises:

- D, E, F and G have one CF each.
- A has two: Fig. 42 omits the second-bar D.
- C has two: Figs. 88a/b use a different, shorter melody.

`I-Distinct.mxl` adds 6 octave transpositions that no Part I exercise uses. They are kept as CF
records with `in_exercises: false` and share a `family_id` with their exercise register. The
Distinct file in turn lacks the two variant melodies (`fux_cf_a_02`, `fux_cf_c_02`). The IDs are
stable for the pinned source: they are numbered per final in the order of first appearance, and the
tests lock them.

## Runtime API (`src/music/fux/`)

```ts
import { loadFuxRepository } from "./src/music/fux/load-node.ts";   // or: new FuxRepository(json)
const repo = loadFuxRepository();
repo.getExercise("fux_2v_fig_005");
repo.getCantusFirmus("fux_cf_d_01");
repo.getSolution("fux_2v_fig_005");
repo.getAnnotations("fux_2v_fig_005");
repo.getExercisesForCantusFirmus("fux_cf_d_01");
repo.getRandomExercise({ species: ["second", "third"], modal_final: "E", cantus_voice: "upper", difficulty: { max: 3 } });
```

The player's answer is a separate `PlayerSolution` (`kind: "player_solution"`), created with
`createPlayerSolution(exercise)`.

- `structuralProblems` and `isComplete` check only well-formedness: no gaps, no overlaps, nothing
  past the final bar, and MIDI consistent with the spelling.
- `compareWithOriginal` is flagged `informational: true`. Matching Fux is never a requirement; rule
  evaluation is a separate, later layer.
